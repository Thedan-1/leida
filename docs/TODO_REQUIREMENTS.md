## 一、QR 码重定位与误差矫正问题 ✅

### 问题描述
1. **部署建图时 QR 码矫正效果差或无效**
   - 横轴明显偏离约 20cm
   - 重新扫描二维码也没有矫正效果
   
2. **矫正逻辑疑问**
   - 矫正一次后，地图坐标系是否就固定了？
   - 当前代码只是记录 `relocalizationOffset` 偏移量，但没有真正修正 ARKit 的坐标系

### 已完成修改 (2026-02-16)
- [x] `detectQRCodes()` 重写为异步，不阻塞 ARKit 帧率
- [x] QR 定位改为四角点求中心（弃用 boundingBox）
- [x] 优先使用 ARKit Raycast 获取真实深度（精度 ±2cm）
- [x] Raycast 失败时用相机内参 + QR 物理尺寸反算深度
- [x] 动态漂移阈值：QR 在画面越小（=越远），阈值越宽容
- [x] 增加巡检时自动重定位开关（冷却 5 秒）
- [x] `tryQRCorrection()` 增加 `isQRCorrectionEnabled` 前置检查
- [x] 增加调试日志，显示检测到的 QR 位置 vs 保存的 QR 位置差值

## 技术要点备忘

### 当前 QR 矫正逻辑问题
```swift
// 当前只是记录偏移量，应用于坐标显示
appModel.relocalizationOffset = offset
appModel.currentPosition = rawPosition + appModel.relocalizationOffset

// 问题：这只影响显示的坐标，不影响 ARKit 内部坐标系
// ARKit 的 Mesh 和其他数据还是用原来的坐标
```

### 应该改成
```swift
// 方案1：保存地图时，把 QR 锚点坐标作为"真实坐标"
// 方案2：导出时对所有顶点应用偏移修正
// 方案3：使用 ARKit 的 setWorldOrigin(relativeTransform:) 修正坐标系
```

### 巡检模式不开 Mesh
```swift
// 加载地图时
let config = ARWorldTrackingConfiguration()
config.initialWorldMap = worldMap
// 不设置 sceneReconstruction
// config.sceneReconstruction = .mesh  // 注释掉

arView.session.run(config, options: [.resetTracking])
```

## 十、未来改进方向 ⏳

### 多 QR 联合校正
- 同时看到多个 QR 码时，取加权平均偏移
- 理论精度可提升到 ±1cm

### 旋转漂移补偿
- 当前 `relocalizationOffset` 只有平移（SIMD3<Float>）
- 如果 VIO 有角度漂移，纯平移校正会随距离发散
- 需要升级为 simd_float4x4 旋转+平移联合校正

### PLY 纹理质量提升
- 增加帧去重（相似视角不重复采集）
- 增加运动模糊检测（模糊帧不采集）
- 支持 Binary PLY 格式（文件更小）
